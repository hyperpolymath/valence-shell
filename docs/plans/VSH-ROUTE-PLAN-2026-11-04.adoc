== 0. Bottom line

[arabic]
. *The spec has to mean what it says.*
* The Lean `isEmptyDir` quantifies over ancestors, so `RmdirPrecondition` is (Inference) uninhabited and the Lean rmdir theorems are vacuous.
* The same vacuity class exists in Idris2 (the hypothesis equals the conclusion), Agda (emptiness is missing) and Z3 (the predicate is uninterpreted).
* CI builds at most 4 of the 12 Lean libraries, and 4 libraries are self-declared broken.
+
Fix all of this first, and make every precondition carry a checked non-vacuity witness.
. *One canonical finite spec.* `FinFS` is a Mathlib-free, decidable finite map with a proved refinement to the current function model. Three things run over it:
* the differential oracle, extended with undo, redo and transactions;
* a golden-trace corpus checked three ways (Rust tests, Lean `decide`, Agda `refl`);
* an in-repo Agda mirror, which serves as the second independent witness.
. *Prove that the shipped Rust refines the spec.* Extract a pure `vsh-core` crate. Run a Charon/Aeneas spike with a 2-session kill rule. If it passes, the refinement theorem becomes F-1's closure.
*The runtime must discharge what the proof assumes.* Fourteen safety failures reproduce today through ordinary `vsh -c` commands (§3.2):
* undo after `cd` deletes the wrong file;
* `cd ..` escapes the sandbox, and so do `>`, `touch`, `mkdir` and the `mv` destination through in-root symlinks;
* `obliterate` on an in-root symlink or hard link destroys the *outside* file's contents;
* a 0600 file comes back as 0644, and its bytes sit in a world-readable state file;
* obliterate in a transaction is reported as rolled back;
* three arithmetic expressions panic;
* obliterate writes its audit record after the irreversible step.
+
These are fixed in Phase 1, in parallel with the Lean work, together with the drift guard and a single shared inverse table. The durability journal (WAL) and its crash-recovery theorem follow in the next session.
. *Feeders wait for G1–G5.* The estate theory attaches later through the same Agda layer.
. *Archival is gated by witnesses.* Coq, Isabelle and Mizar are archived (never deleted) only once Lean and Agda between them give every op ≥2 witnesses.

|*G1 Safety* a|Every case in §3.2 passes through the parsed `vsh -c` path. There is one inverse table for undo, redo and rollback. Ops with no inverse are hard failures in rollback. Obliterate is refused inside a txn. The drift guard stores both fingerprints of each op. It checks the post-state fingerprint before undo and the pre-state fingerprint before redo, because redo runs against the restored pre-state. The undo payload carries the entry kind (with a symlink's `readlink` target), mode, owner and mtime. The session root is fixed and separate from cwd. Every mutation target is contained *after resolution*, not just lexically, with a *per-operation follow policy*:

* *Content operations* (write, append, truncate, redirection, chmod, chown, the cp destination, and *obliterate*) resolve the full path beneath the session root and refuse a target that escapes. Obliterate in particular must never overwrite through a symlink: it opens the target with no-follow semantics beneath the root and refuses a symlink or escaping target before any byte is written.
* *Hard links.* Symlink-safe resolution cannot detect them, so every content operation `fstat`s the opened descriptor. A regular file with `st_nlink > 1` is refused by every content operation, unconditionally. No override flag exists, because an override would bypass the only check that can see the alias. The check is made on the descriptor and repeated with a second `fstat` after the write or overwrite. If the link count changed in between, the op fails loudly and its record gets a *tainted* flag, which is separate from its loss grade; for obliterate, the completion residue records that an alias appeared. *Scope of this guarantee:* it covers aliases that exist when vsh checks, which includes every alias planted in the root beforehand. It does not prevent a *concurrent* same-uid process from creating an alias inside the check-to-write window; that is detected after the fact, not prevented. Such a process already holds write authority over the outside file, so no privilege boundary is crossed. Other users cannot race this way where `fs.protected_hardlinks=1` (recorded in OS-ASSUMPTIONS). The race is closed fully only by the stronger, optional boundary: a session root on its own filesystem, where an outside hard-link alias cannot exist at all. Users who need to edit hard-linked files use that boundary too. Regression: a test-only hook links the target between check and write, and the op reports the alias and its record carries the tainted flag.
* *Directory-entry operations* (rm, rmdir, *mkdir*, *touch/create*, ln, unlink, and *both the mv source and the mv destination*) resolve the parent beneath the root, refusing any parent component that escapes. They then act on the entry itself with `mkdirat`, `openat(O_CREAT\|O_EXCL\|O_NOFOLLOW)`, `unlinkat` or `renameat`, and never follow a final symlink. `rm link` therefore removes the link and leaves the referent alone, as it does today.

Resolution uses `openat2(RESOLVE_BENEATH \| RESOLVE_NO_XDEV)`, or an `O_NOFOLLOW` component walk where that is unavailable. The walk compares each component's mount id (`statx` `STATX_MNT_ID`) with the root's, so a bind mount of an outside directory inside the root is refused, not crossed. A privileged CI regression bind-mounts an outside directory into the root and checks that writes and obliterate through it are refused. If neither `openat2` nor `STATX_MNT_ID` is available (Linux before 5.8), vsh refuses mutations rather than run unchecked. *Platform scope:* the G1 containment guarantee is gated on Linux. macOS, which `compilation_tests.yml` still builds, has neither call. There the walk compares each component's `st_dev` with the root's (`fstatat` with `AT_SYMLINK_NOFOLLOW`); macOS has no bind mounts, so entering another mount changes `st_dev`. A macOS regression attaches a disk image (`hdiutil attach`) mounted inside the root and checks that writes through it are refused. Until that regression is green, the macOS release artefact is withdrawn from the v1 release rather than shipped without containment. `eval_arith` never panics (proptest under both debug and release profiles). |14 safety regressions reproduce |1
|*G2 Durability* |State lives in `$XDG_STATE_HOME/vsh/<sha256(session_root)>/`, mode 0700, files 0600. Writes are atomic. On load, any existing state or journal file is set to 0600 (and its directory to 0700) before it is read. The file is opened with `O_NOFOLLOW`, checked with `fstat` to be a regular file owned by the invoking user, and tightened with `fchmod` on that descriptor, so a symlinked state file is refused rather than followed. A corrupt state is a hard error. `flock` makes a second vsh fail closed. The session root is canonicalised, symlinks and `..` included. A registry of active roots, kept in the state dir under its own lock, refuses a session whose root equals, contains or lies inside an active one. A registry entry is live only while its owner holds that root's `flock`. The lock, not the stored entry, is the source of truth. When acquiring, vsh tries each conflicting entry's lock: if the lock is free, the entry is stale (its process crashed) and is reaped. *Admission is atomic.* vsh takes the registry lock with `LOCK_EX \| LOCK_NB`, retrying for at most one second (B4). While it holds that lock it checks and reaps conflicting entries, takes its own root lock non-blocking, and only then publishes its entry; then it releases the registry lock. On exit it removes its entry under the registry lock *before* releasing its root lock. Every entry is therefore published only by a process that already holds its root lock, and reaped only under the registry lock. A second session can never admit an overlapping root in the gap, and can never reap an entry whose owner is about to take its lock. Regression: two sessions started concurrently on `/work` and `/work/sub`, repeated 1000 times, never both admit. Each entry also records a non-reusable process identity (pid plus process start time) for diagnostics. A killed session therefore never blocks recovery, and the crash-injection runs exercise this path. The guarantee is scoped honestly. The registry coordinates the vsh sessions that share one state namespace, meaning the same user and the same `XDG_STATE_HOME`. Each session also takes an advisory `flock` on the *canonical root directory's own descriptor* (`open(root, O_DIRECTORY)` then `flock(LOCK_EX \| LOCK_NB)`; a conflict is refused immediately with a message naming the root, never waited on, which meets B4's one-second bound), not on a file inside the root. External commands launched from a session could unlink or replace a lock file, but cannot replace the root directory that the session holds open. Cooperating vsh processes with different state namespaces therefore still exclude each other on the same root. Processes that ignore advisory locks (including other users' non-vsh tools) are outside the claim, consistent with R18.

State must also live outside every root it protects. vsh refuses to start when the canonical session root contains its state dir, audit log or key file (for example a root of `$HOME` with the default `XDG_STATE_HOME`), and names the conflicting path. The shell's own commands therefore cannot alter or obliterate their history. An intent/commit journal recovers on startup. Crash injection: 100 kills per PR and ≥1000 nightly. *`JournalModel.recover_sound`* is proved: recovery first compares the path's current fingerprint with the recorded pre- and post-state fingerprints. On a match, an RMR op recovers to \{pre, post}. On a mismatch, because something outside vsh changed the path after the crash, recovery leaves the filesystem untouched and reports `unresolved`. Rolling back could destroy the newer data, and rolling forward would not reach the recorded post-state. RMO ops are different, because an interrupted overwrite leaves a partially overwritten file that is neither. For them the model adds an `incomplete` state, and recovery rolls forward: the recorded intent is completed by finishing the overwrite and unlink. Before rolling forward, recovery opens the path with no-follow semantics and compares its device, inode and incarnation stamp with the identity stored in the intent. If they differ, because the path was replaced while vsh was down, recovery does not touch it and reports an unresolved incomplete obliteration for the user to decide. When the identity check fails, recovery ends in a third terminal state, `unresolved`, with the path untouched and the intent kept. The crash harness's oracle is therefore \{pre, post, unresolved} for RMR and \{post, unresolved} for RMO, where `unresolved` is allowed only when the harness itself changed the path between crash and restart, and a harness case replaces the path between crash and restart to exercise `unresolved`. |Non-atomic, in cwd, corruption swallowed, no lock |1 does the quick part (0600, atomic write, fail-loud load); 2 does the rest

== 10. Tropes, types and logics that may give a more final solution

*Engineering and persistence*

* *Event sourcing* (Inference). One append-only log, with state as a fold. This makes WAL, undo, audit and export a single object with a single recovery proof (P8, `JournalModel`), instead of four that drift apart.
* *Transparency-log Merkle tree* (RFC 6962/9162 style). It replaces the "hash chain called a merkle root" in januskey and in the vsh audit, and gives O(log n) inclusion and consistency proofs. Truncation becomes detectable relative to any signed tree head. This is the principled form of OD-10/OD-24.

*Rust types and grades*

* *Affine types for undo payloads* (Inference, Rust-native). An undo payload is a linear resource: undo consumes it, and obliterate destroys it. In Rust that is a non-`Clone` `UndoToken` that `undo` and `obliterate` take by value. The current `redo_stack` clone (`state.rs:478-486`) is exactly the violation. This mirrors echo-types `EchoResidueCell` (`once-only`) and januskey's Loss grade at the type level, so it is checked by the Rust compiler with no prover.
* *Loss-graded resource algebra.* A single semiring grading each op as lossless, lossy or obliterating. It also carries cost (MaxPlus, tropical `hub_ceiling_le`). One algebra then covers OD-25 (reversibility) and #190/#191 (bounds).

*Proof patterns*

* *Refinement with a runtime-discharged abstraction hypothesis.* The drift guard checks at runtime that the OS state abstracts to the recorded post-state. This is what makes any refinement theorem (P9) say something about the real system.
* *Non-vacuity as a mandatory pattern.* Every precondition gets an inhabitation witness in every prover. This turns a whole defect class into build failures.

*Semantics and observers*

* *Choreographic `two-thread-diamond`* (proved in choreographic-types). This is the theorem shape for F-4's first slice, with independence defined as path non-prefix. It is better than a fresh Lean statement.
* *Noninterference* (secret-types TINI over a down-closed observer lattice). This is the eventual statement form for "an observer at trust tier _t_ cannot learn obliterated content". Combined with absolute-zero's `OND5-composition-leaks`, the claim must be made over the joint observer.
* *Grammar membership as a termination certificate* (jtv-halting-islands-ct pattern). This is the cheap totality story for a verified script subset or arithmetic island.
