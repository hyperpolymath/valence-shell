[[idris]]
== Idris2 `believe_me`: experiment

Goal: prove `(s : String) -> (s == s) = True` without an axiom.

* Direct `Refl` fails under Idris2 0.8.0: "Can't solve constraint between:
  True and intToBool (prim__eq_String s s)". The primitive does not reduce
  on a variable.
* Going through `decEq s s` fails with the same constraint. Idris2's own
  `DecEq String` (`libs/base/Decidable/Equality.idr`, `primitiveEq`) is
  itself `believe_me`, so routing through it would move the axiom into the
  standard library, out of the scanner's sight, without removing it.
* Removing it for real means changing path components from `String` to a type
  with structural equality, which changes the ABI-facing model.

Outcome: `axStringEqRefl` and `axBits8EqRefl` stay as the two registered
axioms (`.machine_readable/IDRIS2_AXIOMS.a2ml`, gated by
`.github/scripts/check-idris2-believe-me.sh`), with an inline Hypatia
allow that names both. The package builds and the gate passes.

Run one test at a time on 2026-11-16, 120 s limit each: 5 fail
(`stress_concurrent_multiple_instances`, `stress_deep_nesting_1000_levels`,
`stress_deep_nesting_no_stack_overflow`, `stress_large_file_undo_streaming`,

=== Repair (2026-11-17)

All 11 tests now pass. The step is back in `compilation_tests.yml` as
`cargo test --test stress_tests -- --ignored --test-threads=1`, Linux only,
with `timeout-minutes: 5` and no `continue-on-error`. No test was deleted or
skipped, and no assertion was loosened.

Shell bugs fixed (`src/state.rs`, `src/commands.rs`):

* *O(n²) persistence.* Every recorded or undone operation rewrote the whole
  history to `.vsh_state.json` (cloned, then pretty-printed). 1,000 touches
  took 5.9 s; 10,000 and 100,000 never finished. The hot path now appends
  one line to `.vsh_state.journal`; the snapshot is rewritten only when the
  journal reaches half the history length (at least 1,024 entries), which
  keeps the cost amortised O(1). Snapshots are written to a temporary file
  and renamed, and record the last journal sequence number they contain, so
  a crash cannot tear the snapshot or replay an entry twice. A torn journal
  line or a sequence gap ends replay and forces the next save to be a full
  snapshot, so operations made after a crash are not stranded behind the
  bad line (Codex review on #229). After the fix, 1,000 touches take
  0.04 s. Seven new unit tests in `state.rs` cover replay, compaction, trim,
  a torn tail, crash-after-rename and transactions; two more cover
  operations after a torn tail and `cd -` surviving a restart (`cd` now
  journals `previous_dir`).
* *O(n²) single-step undo.* Each `undo 1` walked past every already-undone
  operation to pick its target, then searched for that target again from the
  oldest end of the history to mark it. A checked hint for the block of undone operations removes the rescan:
  undoing 10,000 operations one at a time went from 1.8 s to 0.34 s. A unit
  test compares it against a full scan through undo, record, trim and an
  out-of-order mark.
* *Rollback not persisted.* `rollback` cleared the active transaction
  without saving. That had been masked by the next operation's full rewrite,
  and the journal would have exposed it. It now goes through
  `ShellState::abort_transaction`, which saves.

Test expectations corrected (`tests/stress_tests.rs`):

* `stress_concurrent_multiple_instances`, `stress_many_operations_10000`:
  the listings counted the shell's own `.vsh_state*` files. They now exclude
  only those files, and the concurrent test checks the exact set of 1,000
  names.
* `stress_deep_nesting_1000_levels`: `level_NNNN` names give an
  11,000-byte path, past `PATH_MAX`, and the test then ran `mkdir` on paths
  that already existed. It now builds the 1,000 levels through the shell
  with one-character names (about 2,000 bytes, asserted against `PATH_MAX`)
  and undoes them all.
* `stress_deep_nesting_no_stack_overflow`: it only called
  `fs::create_dir_all`, which fails with ENAMETOOLONG at 5,000 levels. It
  now builds the tree with `mkdirat`/`openat`, checks that shell `mkdir` and
  `touch` at that depth fail cleanly without recording anything, and removes
  the tree.
* `stress_large_file_undo_streaming`, `stress_large_file_1gb`: both called
  `touch` on an existing file, but vsh's `touch` only creates files
  (EEXIST). The 100 MB test now runs `rm` (the operation that saves file
  content as undo data) plus `undo` and checks the restored bytes. The 1 GB
  test times `chmod`, `mv` and their undos.
* `stress_undo_redo_efficiency`: "redo" popped the redo stack without
  redoing. It now calls `commands::redo` and checks the files return.
* `stress_resource_limits_max_history`: it now asserts the history is capped
  at `max_history_size` and that the persisted state stays under 32 MiB
  (measured: 2.3 MB).

Still open:

* *Undo data is not streamed.* `rm` reads the whole file into
  `undo_data`, and the journal stores those bytes as a JSON number array
  (about 3 bytes per byte). Removing a 100 MB file takes about 11.5 s in a
  debug build and writes about 300 MB of state. The test name promises
  streaming; the test comment now says it is not implemented. The fix is
  out-of-line undo storage (for example, renaming the file into a store
  under the root), which changes the reversibility implementation, so it is
  left for the owner.
* *History trimming is O(limit) per operation.* At the cap, each new
  operation drains the oldest entry from the front of a `Vec`, moving about
  1.2 MB at the default 10,000 limit. That is about 7 s of the 100,000-op
  test. A `VecDeque` would remove it but changes the public
  `ShellState::history` type that tests and `CLAUDE.md` document as a `Vec`.
* *macOS.* The suite is not run there: `PATH_MAX` is 1024, so the
  1,000-level test cannot pass with absolute paths, and the rest was not
  measured on macOS.
* Neither the journal nor the snapshot is `fsync`ed (the old `fs::write`
  was not either), the files keep the default mode, and they still live in
  the session root. Route plan items E1d and G2
  (`docs/plans/VSH-ROUTE-PLAN-2026-11-04.adoc`) cover fsync, 0600 and moving
  state out of the root; the journal is a new file they must include.
