== What was run (2026-11-17): journal model added

[cols="3,2",options="header"]
|===
| Invocation | Agda 2.7.0.1 + agda-stdlib v2.2 (`6cd04e46`)

| `bash scripts/check-agda.sh` (the invocation above, plus the import-graph
  check), from a clean `_build`
| exit 0; all 14 modules checked
|===

Four modules joined the cone: `JournalFraming`, `JournalReplay`,
`JournalModel`, `JournalWitnesses` (route-plan Phase C, step C1). They carry
the same options, no `postulate` and no escape pragma. Their assumptions are
module parameters, and `JournalWitnesses` builds one instance of all of them,
so the theorems are not vacuous.

What they state, and for what:

* `JournalFraming`: a record is a header that carries the length, then the
  payload, then a checksum. A record cut short
  at any point is rejected (`step-torn`); what the decoder accepts is byte
  for byte a run of well-formed records at the front of the input
  (`decode-sound`). Neither needs any property of the checksum.
* `JournalReplay`: events other than a snapshot or a trim at the history cap
  never remove or reorder history (`run-ids`); after a rollback no operation of that transaction is
  live (`rollback-no-live`).
* `JournalModel`: if a crash keeps the synced bytes and a prefix of the
  unsynced bytes, loading yields the synced events followed by a prefix of
  the unsynced events (`crash-recovery`), so one pending write is
  all-or-nothing (`write-atomic`).

Limits, which the module headers repeat:

* These are theorems about the model. The Rust journal
  (`impl/rust-cli/src/journal.rs`, `state.rs`) was rewritten the same day to
  mirror it, but is not derived from it or proved against it. The link is
  test evidence: the crash-point harness runs the shell on simulated storage
  that implements the model's file and checks every crash image the model
  allows.
* The crash model is an assumption about the storage. It does not cover
  reordered or partly written blocks, or stale bytes in the unsynced region.
* A checksum cannot rule out bytes that were never written as a record but
  happen to match; `decode-sound` says exactly what acceptance means.

Mutation check (2026-11-17, local): six edits were each rejected by the type
checker. They were: a wrong left-over tail and a wrong recovered state in
the worked cases; dropping the checksum test; dropping the canonical-header
test; rollback that marks nothing; and `step-torn` without its "something
was cut off" premise. The unedited tree passed as the control.

=== Added the same day: what the rejected bytes are

A review of the Rust journal found that a changed length field could pass
for an interrupted write. The Rust format gained a check on the length (the
header is now the length followed by four bytes of a hash of it), and the
model gained the matching statements. `bash scripts/check-agda.sh` exits 0
with them; the module count is unchanged at 14.

* The model needed no new test in the decoder. It already accepts a header
  `h` only if it is canonical, `hdr (unhdr h) ≡ h`. For a header that is the
  bare length that holds for every input. For a header that carries a check
  of the length it is the header check.
* `JournalFraming.classify` names the bytes the decoder rejects: `clean`,
  `torn` (the input ends inside a record) or `damaged` (a whole header that
  is not canonical, or a whole record that was still rejected).
* `classify-torn`: a record cut short, with at least one byte kept, is torn.
* `decode-crash-tail`, and `crash-tail` in `JournalModel`: after a crash that
  keeps a prefix of what was appended, the rejected bytes are never
  classified as damaged. A reader that refuses a damaged journal is
  therefore not stopped by a crash.
* `JournalWitnesses` has a second framing instance, `C`, whose header is the
  length and a check cell. There a changed length is damaged
  (`changed-length-is-damage`); with the bare-length header the same change
  is classified as torn (`changed-length-looks-torn`).

Not proved, and not provable: that damage is always classified as damaged.
Damage that leaves a canonical header declaring more bytes than the input
holds is classified as torn (`changed-header-with-matching-check-looks-torn`).
How unlikely that is depends on the strength of the header check, and the
model assumes nothing about it.

Mutation check (2026-11-17, local): four more edits were each rejected. They
were: a body cut short classified as damaged; a header cut short classified
as damaged; a header that is not canonical passed on to the body test; and
the decoder without its canonical-header test. The unedited tree passed as
the control.

== What changed to get there

* *`funext` removed.* Whole-filesystem equalities are now pointwise
  (`_≗_`). Every former `funext helper` proof was already pointwise inside,
  so the theorems keep their content and lose the postulate. Composition uses
  two new congruence lemmas, `fsUpdate-cong` and `applyOp-cong` /
  `applySequence-cong`.
* *K removed.* Clauses that matched `refl` on `p ≡ p` (from `p path-≟ p`)
  now use `fsUpdate-at`, which needs no K.
* *`IsEmptyDir` completed.* It had only an `isDir` field. It now also has
  `noChildren`: no strict descendant (`p ⊑ child`, `child ≢ p`) exists. The
  descendant direction matches Coq and the fixed Lean model.
* *Non-vacuity witnesses.* `PreconditionWitnesses` gives an inhabitant of the
  mkdir, rmdir, createFile, deleteFile and symlink preconditions.

== Warnings

The check prints `UnsupportedIndexedMatch` warnings. They come from matching
`yes` / `no` on the standard library's `Dec`, whose `Reflects` index
needs constructor injectivity that Cubical Agda does not support. The
consequence is that these functions would not compute under cubical
transport. Nothing here is used from Cubical Agda, so they do not affect the
result. Removing them means replacing `Dec` with a non-indexed decision
type throughout; that is recorded as optional clean-up, not done.
